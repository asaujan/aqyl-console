# Aqyl Console

Внутренний пульт для операций по интеграции MMS · Billing (1С) · e-Qural.
Streamlit-приложение, работает локально через VPN GlobalProtect.

## Возможности (v1)
1. **Просмотр синхронизации**: таблица `dl_device_sync` с фильтрами (регион, тип, статус, даты, ПУ) и экспортом в Excel.
2. **Массовый репуш**: загрузка Excel/CSV со списком `device_no` или `id`, автоподбор последних id из БД, прогон через `/api/device-sync-records/{id}/repush` с прогрессом и логом.
3. **Проверка в Billing**: одиночный запрос по ЛС/ПУ и массовая сверка ожидаемого ПУ с фактическим в 1С.

## Установка

```bash
cd aqyl-console
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# заполни .env (БД уже прописана; вставь свежий MMS_COOKIE из DevTools)

streamlit run aqyl_console/app.py
```

Откроется на http://localhost:8501

## Обновление куки
Когда репуш начинает возвращать 401, куки сессии протухли. Обновить можно двумя способами:

**Способ 1 (быстрый, без перезапуска).** Вставь свежую строку Cookie прямо в интерфейсе:
блок "Настройки сессии (куки)" вверху страницы "Массовый репуш" или поле "MMS куки"
в сайдбаре (доступно с любой страницы). Значение держится в сессии и переопределяет `.env`.

**Способ 2 (постоянный).** Пропиши строку в `MMS_COOKIE` в `.env` и перезапусти приложение
(или нажми R в Streamlit).

### Как получить куки
1. Открой http://lifecycle-mgmt.ktga.kz:32068/ в браузере (VPN GlobalProtect включён, hosts прописан).
2. Если разлогинило, войди (admin / eslink@2026).
3. Правая кнопка на странице, Просмотреть код (или Cmd+Option+I на маке).
4. Вкладка Network, фильтр Fetch/XHR.
5. Нажми Query на странице чтобы появился запрос.
6. Клик на строку device-sync-records, вкладка Headers.
7. Прокрути до Request Headers, найди строку Cookie.
8. Скопируй всё значение и вставь в поле в интерфейсе (или в `.env`).
